# Phase 02.1 Plan 05: Paciencia (Klondike) engine + screen Summary

**Fully playable Klondike solitaire (7-column cascading tableau, stock/waste/foundations, tap-to-select-then-tap-to-place interaction) with one legality function per move kind proven to leave state byte-identical on refusal, a bounded engine-level auto-collect, and daily-win castle credit guarded against double-counting.**

## Accomplishments

- `src/ratimos/apps/jogos/klondike_engine.c/.h`: pure C, LVGL-free Klondike engine — a packed-byte card model, a seeded Fisher-Yates deal (local xorshift32, never libc rand/srand), one explicit legality helper per move kind (tableau↔tableau, tableau↔foundation, waste↔tableau/foundation, foundation→tableau, stock→waste, recycle-waste) dispatched through a single `can_move()`/`move()` pair that never mutates state on refusal, auto-flip on exposing a face-down tableau card, win detection, and a bounded `ratimos_klondike_auto_collect()` loop.
- `src/ratimos/apps/jogos/paciencia.c/.h`: cache-once screen mirroring sudoku.c/conexo.c's shape — tap-to-select-then-tap-to-place interaction (not drag-and-drop, which is fiddly over cascaded/overlapping cards on a 320×480 panel), a top zone (stock/waste + 4 foundations at 40×56px) and 7-column tableau (38×54px, 16px cascade overlap) matching UI-SPEC, per-pile `refresh_*()` helpers that clean+rebuild only the changed pile's children, and a visible refusal (accent-border flash via a one-shot `lv_timer`) instead of silently accepting an illegal move.
- Win state: `venceu!` Display-tier banner on win; daily-mode wins credit the shared castle counter exactly once via a persisted `daily_win_recorded` guard, with `+1 no castelo` shown only after a successful credit. `recolher` (auto-collect) and `novo jogo` (always available, destructive-confirm) round out the endgame/reset affordances; `novo jogo` clears only the saved board, never the shared progression.
- `jogos_app.c`: paciencia's launcher row now opens `ratimos_paciencia_show` (third of five games wired, after sudoku and conexo).
- 21 Unity tests in `test_jogos_paciencia`, including the load-bearing deal-integrity (all 52 cards exactly once) and illegal-move-leaves-state-byte-identical (`memcmp`) checks, plus auto-collect's bounded-termination behavior in both directions (zero available, clears everything available). Full project suite: 100 tests, 97 pass (the 3 pre-existing `test_sync_integration` failures are environment-secret-gated and unrelated to this plan, same as documented in 02.1-04).

## Decisions Made

- `RATIMOS_KLONDIKE_MAX_PILE` raised from the plan's suggested 20 to 32 after the first Task 1 test run failed with corrupted counts and a SIGINT crash — the stock pile alone starts a deal holding 24 cards, so a 20-slot `cards[]` array silently overflowed into the adjacent `waste` pile's memory. 32 comfortably covers the 24-card stock/waste worst case plus a generous tableau-run margin, and the struct still fits well under the 512-byte save blob (no need to shrink anything).
- Card color is computed via explicit suit comparison (`suit == diamonds || suit == hearts`), not the plan's suggested `suit & 1` bit-parity shortcut — with the documented `clubs=0/diamonds=1/hearts=2/spades=3` ordering, that shortcut would incorrectly classify hearts (2) as black.
- Stock draws one card per tap (`RATIMOS_KLONDIKE_DRAW_COUNT = 1`, Klondike "draw-1") rather than draw-3 — simpler to reason about and tap on a small touch screen; the plan explicitly left this choice open.
- `ratimos_klondike_auto_collect()` is implemented in the LVGL-free engine (not inline in paciencia.c's `recolher` callback) specifically so its bounded-loop contract (terminates immediately when nothing is available, clears everything available within the 200-move cap) is directly unit-testable without a rendered screen — mirrors conexo's precedent of keeping win/loop-guard logic engine-side and testable.
- All new UI copy stays ASCII-only (`recomecar`, `comecar`, no cedilla/accents) — the plan's own action text mixed ASCII and accented forms for the same confirm dialog, and the codebase's already-documented convention (established twice, in 02.1-01 and 02.1-04) is to substitute unaccented equivalents everywhere new copy is introduced, not only inside the bitmap-font-constrained title labels.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `RATIMOS_KLONDIKE_MAX_PILE=20` overflowed the stock pile's fixed-size array on deal**
- **Found during:** Task 1's first `pio test -f test_jogos_paciencia` run
- **Issue:** The plan's suggested pile capacity (20) only accounted for a plausible worst-case tableau column length, not the initial 24-card stock pile. Dealing wrote 24 cards into a 20-slot `cards[]` array, overflowing into the adjacent `waste` pile's memory in the struct and corrupting subsequent fields — surfaced immediately as two failing assertions (`test_deal_contains_all_52_cards_exactly_once`, `test_deal_tableau_columns_have_correct_size_and_exactly_one_face_up`) followed by a SIGINT crash at the end of the test run.
- **Fix:** Raised `RATIMOS_KLONDIKE_MAX_PILE` to 32 (covers the 24-card stock/waste worst case with margin) and updated the header comment explaining the sizing rationale; re-verified `_Static_assert(sizeof(ratimos_klondike_state_t) <= RATIMOS_GAME_STATE_BLOB_SIZE)` still holds with plenty of headroom (~444 bytes vs. the 512-byte ceiling).
- **Files modified:** `src/ratimos/apps/jogos/klondike_engine.h`
- **Verification:** Full 17-test Task 1 suite green afterward; no further failures across the rest of the plan's test additions.
- **Committed in:** `b581c76` (Task 1 commit — the bug was caught and fixed before the first commit)
