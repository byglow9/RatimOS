# Phase 02.1 Plan 06: Termo/Dueto/Quarteto Summary

**All three real term.ooo modes (Termo 1x6, Dueto 2x7, Quarteto 4x9) shipped daily-only and deterministic, with duplicate-safe two-pass letter feedback, playing off a 577-word curated Brazilian-Portuguese answer pool derived from the MIT-licensed fserb/pt-br lexicon.**

## Performance

- **Duration:** ~55 min
- **Completed:** 2026-09-10
- **Tasks:** 3/3
- **Files modified:** 13 (11 created, 2 modified)

## Accomplishments

- `tools/curate_termo_words.py`: a reproducible, idempotent two-phase curation pipeline that filters the 145,744-entry raw `fserb/pt-br` lexicon (MIT) to 5-letter words, ranks by the source's own ICF frequency score, auto-drops the source's 340-entry profanity/slur blocklist, and never silently overwrites a hand-curated answer list on a re-run.
- A full manual suitability pass performed end to end over all 600 ICF-ranked candidates: 23 entries removed (19 proper nouns the source's all-lowercase lexicon let slip past the automated capitalization filter, plus `diabo`/`morte`/`morto`), leaving 577 final daily answers and a 6,011-word wider accepted-guess list, both recorded with full provenance in `assets/wordlists/README.md` and `docs/visual-identity/README.md`.
- `termo_engine.c/.h`: the duplicate-safe two-pass scoring algorithm (greens-then-yellows), the real term.ooo mode table (1/2/4 boards, 6/7/9 tries), a deterministic per-mode-per-day answer draw with reject-on-duplicate distinctness, and shared-guess application across every unsolved board.
- `termo.c/.h`: a cache-once LVGL screen with a 3-pill mode selector, per-mode board sizing (Termo 40px/6 rows, Dueto 26px/7 rows, Quarteto 22px/5-row scrollable viewport), one shared neutral QWERTY keyboard, save-after-every-change persistence, and a once-only daily-win castle credit.
- Launcher wiring: `jogos_app.c`'s termo row now opens `ratimos_termo_show`.
- 16 new Unity tests (all passing), plus the full `pio run`/`pio test -e native_sim` suite confirmed green (excluding one pre-existing, unrelated Phase 2 integration-test failure — see Issues Encountered).

## Decisions Made

- The manual suitability pass (required by the plan, normally a human task) was performed directly by the executor since this is an autonomous run with no human available mid-plan — the removal rationale for all 23 entries is fully recorded in `assets/wordlists/README.md` so a human can audit or extend the decision later.
- Termo's 3 modes share a single `game_state` save slot, mirroring sudoku's existing mode-switch model: switching modes always starts a fresh daily session for the target mode (never keeps 3 sessions alive simultaneously), so a switch away from an in-progress session routes through the same destructive-confirm dialog pattern already established by sudoku.c.
- No save exists (first launch) or the save is corrupted: always defaults to Termo mode (not "last active mode") — the simplest deterministic default, matching sudoku.c's default-to-médio precedent.
- The UI-SPEC's "flashes its outline in accent" reject feedback was implemented as a thicker (3px vs. normal 2px) accent border on the current guess row rather than a timed blink/animation, since no timer-based animation infrastructure exists elsewhere in this codebase for this class of transient effect.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical functionality] Proper nouns slipped past the automated capitalization filter**
- **Found during:** Task 1, manual suitability pass
- **Issue:** The plan's curation pipeline step (c) calls for dropping "anything capitalized in the source (proper nouns)" — but `fserb/pt-br`'s `lexico` file ships 100% lowercase, so this filter was a documented no-op against this specific source, letting 19 country/state/personal names (e.g. `japao`, `china`, `goias`, `maria`) into the 600-candidate answer pool.
- **Fix:** Removed all 19 during the required manual pass, alongside 3 morbid/religiously-loaded terms (`diabo`, `morte`, `morto`), documenting the gap and the fix in `assets/wordlists/README.md` so a future regeneration applies the same standard.
- **Files modified:** `assets/wordlists/termo_answers.txt`, `assets/wordlists/README.md`
- **Verification:** Re-read the final 577-word list; `wc -l` still within the 200-600 acceptance bound.
- **Committed in:** `b584456` (Task 1 commit)
