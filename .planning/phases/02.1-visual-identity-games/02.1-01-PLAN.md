<assumption_delta_decision>
The `assumption-delta` detector fired (`kind: pluralization`) on this phase's scope. The real
identity shift behind the signal is not "another app" — it is that the Storage/Content API is
gaining its **first mutable domain**. Until now the API's implicit primary noun was *read-only
content the device displays* (`index_*()` reads fixtures once, `list_*()` copies from a static
cache, nothing is ever written).

- **Primary noun after this plan:** *storage domain* — a named content area that is always
  readable and **may** be writable. `letters`/`photos`/`tracks`/`games`/`settings` are the
  read-only variant; `game_state` is the read-write variant.
- **Decision: `promote`.** `content_api.h` keeps being the one and only storage contract, and the
  write capability is added *inside* it as a domain that declares get/save/clear. The rejected
  alternative (`add-alongside`) would have meant a second, parallel persistence path — game files
  calling C stdio directly — which D-10 explicitly forbids and which would leave the "apps never
  touch storage" rule true only for the older half of the codebase.
- **Invariant test (accepted, implemented as an acceptance criterion in Task 1):** no file under
  `src/ratimos/apps/jogos/` opens or writes a file directly; every byte that reaches disk goes
  through `src/storage/`. This goes red the instant a future game reintroduces an ad-hoc save path.
</assumption_delta_decision>

    **3. `src/storage/game_state.c` (new — the first write-capable domain).** Implement with C
    standard-library stream I/O in binary mode. Fixed compiled path table only (V12 discipline
    inherited from `letters.c`/`photos.c` — never build a path from content-derived input, never
    scan a directory): `assets/save/sudoku.bin`, `assets/save/paciencia.bin`, `assets/save/termo.bin`,
    `assets/save/cruzadinha.bin`, `assets/save/conexo.bin`, and `assets/save/progression.bin`.
    `ratimos_storage_index_game_state()` creates the `assets/save/` directory if absent (via the
    POSIX `mkdir` from `sys/stat.h`, ignoring an already-exists error) and does no other work.

    On-disk record = a fixed header followed by the full 512-byte blob. Header fields, in this order:
    `uint32_t magic` (compile-time constant `RATIMOS_SAVE_MAGIC` 0x524d4753), `uint16_t format_version`
    (`RATIMOS_SAVE_FORMAT_VERSION` 1), `uint16_t game_kind`, `uint32_t used`, `uint32_t checksum`
    (a plain 32-bit additive sum over the 512 blob bytes). Write path: build the record in a local
    struct, stream it to `<path>.tmp`, close it, then `rename()` the temp over the real path so an
    interrupted or killed process can never leave a half-written file that loads as valid. Read path
    must validate before trusting anything (ASVS V5): stat/read the whole record, then reject unless
    every one of these holds — total bytes read equals the expected record size, magic matches,
    format version equals 1, `game_kind` is below `RATIMOS_GAME_COUNT` **and** equals the requested
    kind, `used` is <= `RATIMOS_GAME_STATE_BLOB_SIZE`, and the recomputed checksum matches. Any
    single failure zeroes `*out` and returns `RATIMOS_GAME_STATE_INVALID`; a missing file returns
    `RATIMOS_GAME_STATE_ABSENT` with `*out` zeroed.

    Progression uses the same header/atomic-rename discipline against its own path, with its own
    validation: clamp `shared_completions` to `RATIMOS_PROGRESSION_MAX_COMPLETIONS`, and normalize
    every `game_exclusive_unlocked[i]` to 0 or 1. `ratimos_storage_record_daily_win(game)` loads
    (falling back to an all-zero state on absent/invalid), rejects an out-of-range `game`, increments
    `shared_completions` unless already at the clamp ceiling, sets `game_exclusive_unlocked[game]` to
    1, saves, and returns success. It must never decrement any field.
    `ratimos_storage_clear_game_state(game)` removes only that game's board file and must not touch
    the progression file at all.

    Add a file-header comment in the codebase's existing PT-BR style stating this is
    `native_sim`-only file-backed persistence and that the hardware phase (Phase 5) replaces the
    stream calls here with the real SD/NVS write path while keeping these function signatures
    unchanged.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| disk → process (`assets/save/*.bin`) | Untrusted input crosses here on every launch. The blob can be truncated by a killed process, corrupted by a future full SD card, or hand-edited. It is then used to size loops and index fixed C arrays. |
| dev machine → repo (`assets/save/`) | Runtime-written personal play data must not cross into version control. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02.1-01 | Denial of Service | `src/storage/game_state.c` load path | high | mitigate | Task 1 + Task 3: fixed-size record with magic, format version, `used` bound, and additive checksum; any failure zeroes `*out` and returns `RATIMOS_GAME_STATE_INVALID`; caller starts a fresh game with visible copy instead of crashing |
