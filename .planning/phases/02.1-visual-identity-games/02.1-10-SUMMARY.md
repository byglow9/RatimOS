# Phase 02.1 Plan 10: Topbar/sectionbar visual rework (system logo, pixel battery, file-explorer breadcrumb) Summary

**Closed the header/navigation half of UAT gap G-02.1-4: the topbar now shows the user-supplied rook logo (processed through the real icon pipeline) with a pixel shadow, a drawn pixel-art battery, and the real PC clock; the sectionbar renders a muted/accent file-explorer breadcrumb from a single recolored label instead of a flat title, with zero LV_SYMBOL_HOME/LV_SYMBOL_BATTERY_FULL/LV_SYMBOL_OK glyphs left in either bar.**

## Accomplishments
- `tools/prepare_system_rook.py` turns the sketch's ~500-color chroma-keyed reference PNG into a 6-color, hard-edged, 14x20px source compatible with the existing `LV_COLOR_FORMAT_I4` 16-color budget, compiled as the icon set's 12th entry via the unmodified `tools/convert_images.py`
- `ratimos_topbar_create()` replaces both LVGL symbol-font glyphs (home icon, battery icon) with real pixel-art: the rook logo with a hard 2px pixel shadow, and a drawn bordered/filled battery rectangle at a documented mock charge percentage
- `ratimos_topbar_create()`'s clock now reads the real PC wall-clock time once at build time (still not "live" across a cached screen session, documented in-line as the Phase 4 RTC follow-up)
- `ratimos_sectionbar_create()`/new `ratimos_sectionbar_set_path()` render a single recolored label as a growing file-explorer path (`./home/jogos/conexo`) with muted parent segments and an accent-highlighted current segment, removing the old `LV_SYMBOL_OK` checkmark object entirely (sectionbar row is now exactly one child)
- 5 new headless-LVGL Unity tests (`test/test_status_bar`) pin the breadcrumb split rule, the single-child contract, and `create()`/`set_path()` formatting convergence

## Decisions Made
- Sectionbar depth rule (>=2 slashes triggers the muted/accent split; a single-level path stays plain `RATIMOS_COLOR_TEXT`) resolves an internal ambiguity in the plan between its `<behavior>` examples (which explicitly call for `"./home"` to render entirely in the body-text color) and its more literal `<action>` prose (which read as "any path containing a `/` splits") -- followed the `<behavior>` block since it is the TDD-authoritative contract for this task and both stated examples are satisfied exactly.
- Battery charge-fill deliberately uses `RATIMOS_COLOR_TEXT` instead of the sketch CSS reference's `--ratimos-game-correct` token, because `theme.h` explicitly documents the 7 game-semantic colors as gameplay-board-only and forbids their use as chrome; the topbar battery is chrome.
- `docs/visual-identity/README.md`'s provenance table was intentionally left unchanged -- it is not in this plan's declared `files_modified` frontmatter list, so adding a `system_rook` row there is out of this plan's scope (not required by any acceptance criterion).

**2. [Rule 1 - Bug] Acceptance grep literal mismatch (Portuguese vs. English phase reference)**
- **Found during:** Task 3 acceptance verification
- **Issue:** Project source comments are conventionally written in Portuguese ("Fase 4"), but the plan's own acceptance criterion greps for the literal English string `'Phase 4'` (matching how `ROADMAP.md`/`REQUIREMENTS.md` tag phase cross-references, e.g. `| SHELL-02 | Phase 4 | Pending |`). - **Files modified:** src/ratimos/status_bar.c
- **Verification:** `grep -c 'Phase 4' src/ratimos/status_bar.c` returns 3 (>=2 required).
- **Committed in:** 05afad7 (Task 3 commit)

**3. [Rule 1 - Bug] Test suite initially indexed the wrong LVGL object**
- **Found during:** Task 2, first `pio test -e native_sim -f test_status_bar` run
- **Issue:** The first draft of `test_status_bar.c` called `lv_obj_get_child(parent, 0)` expecting the sectionbar's title label, but `ratimos_sectionbar_create()` creates a `row` object as the child of `parent` and the label as a child of `row` -- the test was asserting properties (class, recolor flag, text) on the row object, not the label, causing `TEST_ASSERT_EQUAL_PTR`/`TEST_ASSERT_EQUAL_STRING` failures and a subsequent SIGSEGV from calling label-only accessors on a non-label object.
- **Fix:** Corrected every test to fetch `row = lv_obj_get_child(parent, 0)` then `label = lv_obj_get_child(row, 0)`.
- **Files modified:** test/test_status_bar/test_status_bar.c
- **Verification:** All 5 tests pass, no crash.
- **Committed in:** 8b40b52 (Task 2 commit; fixed before the commit was made, not a follow-up patch)
