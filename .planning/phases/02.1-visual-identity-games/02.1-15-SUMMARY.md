## Why cruzadinha cost about 194KB (02.1-12) / 170KB (here), and what changed

I measured it by deleting the screen's subtrees one at a time with the screen loaded and reading `ratimos_heap_used()` before and after each deletion. This was a temporary probe and is not committed.

| block | bytes freed |
| --- | --- |
| 11x11 grid (121 cell `lv_obj` + 121 letter labels + 121 number labels) | **124,968** |
| clue-list modal (scrim + panel + 2 x 16 hidden panel rows with labels) | **29,544** |
| confirm modal | 3,368 |
| actions row (3 bevel buttons) | 3,048 |
| keyboard (buttonmatrix) | 1,408 |
| other content (error/banner/castle labels) | 1,080 |
| clue strip | 680 |
| shell (bg image, topbar, sectionbar, bottombar) | 6,472 |
| **total** | **170,568** |

The grid was the cause: about 1KB per cell. That is 3 objects, each with its own local style arrays (bg color/opa, border color/width, radius, text color/font, the align/position properties from `lv_obj_center` and `lv_obj_align`), heap-allocated label text, and TLSF block overhead. The rest came from building a 32-row list on every visit that the player rarely opens. The 02.1-12 figure (~194KB, 34%) was measured with the other screens still cached around it, so fragmentation was worse.

Fixes applied:
- **Grid:** now one `lv_obj` drawn in `LV_EVENT_DRAW_MAIN` (`board_draw_cb`). Per cell it draws the background and border (selected / active entry / normal / block variants unchanged), the clue number in mono 10 at the top-left one pixel inside the border, and the typed letter centered in the theme font. It reproduces the old layout arithmetic exactly. `board_clicked_cb` maps the tap point to (row, col) and ignores block cells, as before.
- **Clue list:** built in `ver_todas_clicked_cb` and deleted by `close_clue_list()`, both from "fechar" and after picking a clue.

## Decisions Made

- Old screens are deleted **immediately** (`lv_screen_load_anim(..., auto_del=true)` with 0ms), not with `lv_obj_delete_async`. This keeps the numbers deterministic for tests. LVGL 9.5 marks events of deleted objects (`e->deleted`) and resets indevs that point at them. `test_real_pointer_tap_on_voltar_deletes_old_screen_cleanly` drives a real pointer indev through press and release on "voltar" for all 5 games.
- There is **no LRU**. Game state already comes from storage on every build, so a cached game screen would only save rebuild time and would cost up to 139KB.
- `LV_OBJ_FLAG_USER_1` marks a persistent screen. The splash still uses a plain `lv_screen_load()` and gets deleted when the home loads through the helper.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] Static widget handles nulled on delete in every module, not just the screen pointer**
- **Found during:** Task 2
- **Issue:** The plan asked for the `s_*_screen` pointers to be cleared. Paciencia's flash `lv_timer` calls `render_all()` on widgets that would no longer exist. jogos_app's `refresh_jogos_rows()` would dereference stale label handles if a rebuild hit the empty state. Termo's pending rejection message would also have leaked into the next visit.
- **Fix:** Each module's `*_screen_deleted_cb` nulls every widget handle. Paciencia also deletes its timer; termo clears `s_reject_msg` and `s_reject_flash`.
- **Commit:** 3d3cf82

**2. [Rule 2] Removed the test-only 512KB heap pool from test_game_screens**
- **Found during:** Task 2
- **Issue:** That pool existed only to hide this leak (its comment said so). Keeping it would have stopped the suite from catching a regression.
- **Fix:** Removed the pool and replaced the ordering comment.
- **Commit:** 3d3cf82

**3. Reusable heap probe placed in src/ instead of a test-only helper.** The coordinator asked for a clear way for 02.1-16 to measure heap; that is now `src/ratimos/heap_probe.h`. Committed in c0b3e74.

Otherwise the plan was executed as written.
