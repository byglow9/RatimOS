# Phase 02.1 Plan 07: Cruzadinha (crossword) Summary

**A real crossword game shipped end to end: a dev-time backtracking/CSP generator turns hand-authored PT-BR word+clue lists into 5 compiled puzzles (4 on a 9x9 grid, 1 on 11x11), a geometry-driven engine numbers and validates them, and a cache-once LVGL screen makes them playable with a contextual clue strip, a full browsable clue list, and daily-progression crediting.**

## Performance

- **Duration:** ~85 min
- **Completed:** 2026-09-10
- **Tasks:** 3/3
- **Files modified:** 13 (10 created, 3 modified)

## Accomplishments

- `tools/generate_crossword.py`: a from-scratch backtracking/CSP grid-placement generator (no third-party crossword library dependency) that reads a JSON word+clue list, searches for a valid intersecting layout respecting the standard crossword adjacency rules, and emits a compiled C puzzle bank plus the standard left-to-right/top-to-bottom clue numbering. Deterministic (idempotent reruns produce byte-identical output) and fails loudly with the offending puzzle id if its node budget is exhausted rather than emitting a broken grid.
- A real bug in the generator's own correctness was found and fixed during development: the initial grid model let two different across entries (or two down entries) silently claim the exact same starting cell when one word was a letter-for-letter prefix of another placed in the same row (`FLOR`/`FLORESTA`). Fixed by tracking per-cell orientation ownership, verified by re-running the full generator and confirming zero collisions across all 5 puzzles.
- 5 hand-authored, project-owned Brazilian-Portuguese crosswords (`cruz-001`..`cruz-005`, warm everyday-life themes: casa, natureza, comida, animais, cotidiano), 8-10 words each, 4 on a 9x9 grid and 1 on 11x11 (documented as genuinely needing the larger grid).
- `cruzadinha_engine.c/.h`: pure-C engine mirroring `termo_engine.h`'s shape -- geometry-derived numbering (never trusts the generator's stored numbers, making a mismatch detectable), full-bounds entry resolution, validated letter entry, per-entry/whole-puzzle completion, and clue-number-ordered next-unsolved cycling with wraparound.
- `cruzadinha.c/.h`: a cache-once screen with a variable-size grid (built once at the 11x11 maximum, shown/hidden/resized per puzzle), a ~40px contextual clue strip with a "proxima palavra" cycling affordance, a scrollable "ver todas as dicas" full clue-list overlay grouped into horizontais/verticais, a shared A-Z+apagar keyboard, save-after-every-change persistence with `T-02.1-02` restore validation (puzzle_index re-resolved through the bank, cursor/active-entry bounds-checked against the puzzle's own dimensions), the defensive empty-bank copy, and a once-only daily-win castle credit.
- Launcher wiring: `jogos_app.c`'s cruzadinha row now opens `ratimos_cruzadinha_show` -- all 5 games are now reachable from the launcher.
- 14 new Unity tests (all passing), plus the full `pio run`/`pio test -e native_sim` suite confirmed green (excluding the pre-existing, unrelated `test_sync_integration` failure -- see Issues Encountered).

## Decisions Made

- Grid size is decided per-puzzle by whether the hand-authored word list actually needs it: 4 of 5 puzzles fit comfortably on 9x9, the 5th needed 11x11 -- both sizes are within the UI-SPEC's declared bound (9x9 default, 11x11 only when genuinely needed).
- The generator's search strategy is try-any-remaining-word backtracking (not fixed placement order) -- a fixed longest-word-first sequence dead-ended almost immediately on real word lists even when every word shared letters with every other, because it couldn't recover from a single bad early placement choice.
- Cruzadinha's clue text is 100% project-authored for this initial 5-puzzle set; no network access was available in this session to fetch the optional Dicionario-Aberto (CC BY-SA 2.5 PT) seed dataset D-12 accepted. Provenance records this honestly rather than claiming a derivation that didn't happen, and documents the attribution/share-alike obligation for any future contribution that does derive clue text from it.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Generator's per-cell model allowed two across (or two down) entries to collide at the same starting cell**
- **Found during:** Task 1, manual verification of the first successful generator run
- **Issue:** The initial grid representation stored only a letter per cell. A shorter word that was an exact letter-for-letter prefix of a longer word placed starting at the same cell in the same row (`FLOR` vs `FLORESTA`) both passed the before/after adjacency check independently, producing two declared entries occupying an overlapping run of cells -- an invalid crossword structure that would have shipped silently.
- **Fix:** Changed the grid representation to track per-cell orientation ownership (a cell records whether an 'across' and/or a 'down' entry already claims it), so `can_place()` now rejects a second across (or second down) claim on any cell already owned by that orientation, while legitimate across/down crossings continue to work.
- **Files modified:** `tools/generate_crossword.py`
- **Verification:** Regenerated all 5 puzzles; a post-generation scan confirmed zero `(row, col, is_across)` collisions across the whole bank; `pio run -e native_sim` and the new Unity suite both pass.
- **Committed in:** `1f0e97f` (Task 1 commit -- caught and fixed before the first commit, not a follow-up patch)
