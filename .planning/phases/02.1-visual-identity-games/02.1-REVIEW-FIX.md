## Fixed Issues

### CR-01: "novo jogo" / mode-switch lets sudoku, termo, conexo, and cruzadinha re-credit the same daily win multiple times

**Files modified:** `src/storage/content_api.h`, `src/storage/game_state.c`,
`src/ratimos/apps/jogos/sudoku.c`, `src/ratimos/apps/jogos/paciencia.c`,
`src/ratimos/apps/jogos/termo.c`, `src/ratimos/apps/jogos/conexo.c`,
`src/ratimos/apps/jogos/cruzadinha.c`, `test/test_storage_game_state/test_storage_game_state.c`
**Commit:** 6b1dd68
**Applied fix:** Implemented the review's recommended option 1 (storage-layer
day-scoped idempotency, "protects every current and future caller"). Added a
`last_win_day_index[RATIMOS_GAME_COUNT]` array to `ratimos_progression_state_t`
/ `progression_record_t` (persisted, included in the existing progression
checksum automatically since it sits after `shared_completions` in the
record), with a `RATIMOS_NO_WIN_DAY` (`UINT32_MAX`) sentinel for "never
credited" so a freshly-zeroed/missing progression file is never mistaken for
"already credited on day 0". `ratimos_storage_record_daily_win()` now takes an
explicit `uint32_t day_index` parameter and short-circuits as an idempotent
no-op (`return true` without incrementing) if this game already credited on
that same day — this guard lives entirely at the storage layer, so it survives
any client-side reset of the in-memory/persisted `daily_win_recorded` byte
(exactly the bypass the finding describes for sudoku/termo/conexo/cruzadinha's
"novo jogo"/mode-switch flows). All 5 call sites were updated to pass
`ratimos_daily_index()` (already available in every game file via the existing
`daily_seed.h` include). Updated `test_storage_game_state.c`: the old test that
explicitly proved the double-credit bug
(`test_record_daily_win_twice_increments_counter_but_flag_stays_one`) was
replaced with three tests that pin the new contract:
`test_record_daily_win_same_day_twice_is_idempotent` (same day, same game →
no double credit), `test_record_daily_win_different_day_increments_again`
(different day, same game → legitimate new credit), and
`test_record_daily_win_same_day_different_game_both_increment` (per-game
isolation of the guard). All 25 tests in `test_storage_game_state` pass, and
all 96 tests across the 5 game suites + `test_progression` pass unchanged.

**Note for human verification:** this fix changes the on-disk progression save
format (adds a field to `progression_record_t`, growing it from 20 to 40
bytes) and the public signature of `ratimos_storage_record_daily_win()`. Any
existing `assets/save/progression.bin` written by a prior build will now fail
the exact-size check in `read_exact()` and be treated as "no progression yet"
(reinitializes to zero + `RATIMOS_NO_WIN_DAY` sentinels) rather than being
rejected outright — consistent with the file's existing "never lose a real
win to a missing/invalid file" policy, but worth a deliberate look since this
is a save-format change touching the core gift-progression mechanic. Please
manually confirm the day-scoping semantics (crediting keyed on
`ratimos_daily_index()`, i.e. calendar day per the native_sim host clock) match
the intended product behavior before this phase is considered fully verified.

### WR-01: Crossword clue text has no ASCII/charset validation, unlike answers

**Files modified:** `tools/generate_crossword.py`
**Commit:** b0b8896
**Applied fix:** Added an `isascii()` check to `validate_clue()` mirroring
`validate_answer()`, plus an explicit UTF-8 byte-length check
(`len(clue.encode("utf-8")) > 95`) against the real C buffer capacity
(`char clue_text[96]`, 95 usable bytes + NUL), as suggested. Verified by
regenerating the crossword bank from the current `assets/crosswords/wordlists.json`
(`python3 tools/generate_crossword.py --in ... --out-c /tmp/... --out-h /tmp/...`)
and diffing against the committed `cruzadinha_puzzles.c`/`.h` — byte-identical
output (aside from the expected header-filename line), confirming the new
validation doesn't reject any existing clue. Python syntax verified via
`ast.parse()`.

### WR-02: `daily_seed.c` silently returns a colliding seed if `stream` values are ever allowed to reach 32

**Files modified:** `src/ratimos/apps/jogos/termo_engine.c`
**Commit:** d9c3bf9
**Applied fix:** Added two `_Static_assert`s next to `termo_daily_seed()`
(which already has visibility into `RATIMOS_GAME_COUNT` via the existing
`content_api.h` include in `termo_engine.h`): one guarantees the raw
`ratimos_game_kind_t` values (0..`RATIMOS_GAME_COUNT`-1) never reach the
offset-8 window reserved for termo, and one guarantees termo's own highest
offset (`8 + RATIMOS_TERMO_MODE_COUNT - 1`) stays strictly below the 32-wide
daily-seed stride. A future 6th game or 4th termo mode that would silently
collide now fails the build instead. Verified with `pio test -e native_sim -f
test_jogos_termo` (16/16 passed).

### WR-03: sudoku.c "novo jogo" reset on solved diário board is the primary user-visible trigger for the double-credit bug

**Files modified:** none (resolved as a direct consequence of CR-01)
**Commit:** 6b1dd68 (same commit as CR-01)
**Applied fix:** The review explicitly states "once CR-01 is fixed at the
storage layer, this resolves itself" — confirmed: sudoku's "novo jogo" pill
still regenerates the diário board via `switch_to_mode()`/`memset`, clearing
the client-side `daily_win_recorded` flag exactly as before, but re-solving
the identical daily board now calls
`ratimos_storage_record_daily_win(RATIMOS_GAME_SUDOKU, ratimos_daily_index())`,
which is a no-op for the same day (per CR-01's storage-layer guard). The
client flag still gets set back to `1` (the function returns `true` for the
idempotent no-op case too), so the UI behaves correctly without any
sudoku.c-specific special-casing. No separate code change was needed or made.

### WR-04: `render_clue_list` clue-list overlay rows keyed by raw array index without validating the `RATIMOS_CRUZADINHA_MAX_WORDS` split invariant

**Files modified:** `src/ratimos/apps/jogos/cruzadinha.c`
**Commit:** 00e5177
**Applied fix:** Added `if (across_count >= RATIMOS_CRUZADINHA_MAX_WORDS) break;`

native_sim -f test_jogos_cruzadinha` (14/14 passed).
