# Phase 02.1 Plan 02: Visual Identity Summary

**Project-authored pixel-art icon pipeline (LV_COLOR_FORMAT_I4) plus a two-tier Press Start 2P pixel typography system, wired into the home screen and sectionbar, with a grep-checkable provenance/distinctness record against colombiaOS.**

## Accomplishments

- `tools/convert_images.py`: a manifest-driven, deterministic Pillow pipeline generalizing `convert_logo.py` to `LV_COLOR_FORMAT_I4` indexed images (16-entry BGRA palette prepended, 2 pixel indices packed per byte) — layout verified directly against LVGL's own `img_cogwheel_indexed16.c` example asset and `lv_bin_decoder.c`'s indexed-decode nibble order before writing a single byte.
- `tools/generate_icon_art.py`: eleven 32x32 pixel icons (five home-section icons, `home_castelo`, five game icons) drawn procedurally from Pillow primitives in exactly two theme colors — no external editor, no external reference imagery, fully reproducible from committed source.
- `tools/convert_title_font.sh`: pinned `npx lv_font_conv@1.5.3` wrapper producing `ratimos_font_title_16`/`_20` from Press Start 2P (SIL OFL 1.1) — full PT-BR accented-glyph coverage confirmed on the very first conversion run, so the Pixel Operator fallback was never invoked.
- `ratimos_badge_create()` reinterprets its argument as an icon id first (via `ratimos_icon_by_id()`), rendering a circle-clipped `lv_image`; `NULL`/unknown ids fall through unchanged to the original circle+letter rendering — every existing call site kept compiling with zero changes beyond the 5 home-tile icon ids.
- `docs/visual-identity/README.md`: the checkable artifact behind ROADMAP success criterion 1 — a full asset provenance table and a colombiaOS distinctness record, with colombiaOS named exactly once, in that file only.

## Decisions Made

- Icon art authored via a committed procedural script rather than an external pixel-art editor — stronger provenance auditability, explicitly documented as a production-method deviation from the UI-SPEC's suggested (not mandated) Piskel/Aseprite path.
- Press Start 2P locked immediately after its first `lv_font_conv` run confirmed full PT-BR glyph coverage (cmap analysis: 95/95 ASCII + 24/24 accented symbols present, zero missing-glyph warnings) — no need to trial Pixel Operator.
- Icon glyph colors restricted to `RATIMOS_COLOR_TEXT`/`RATIMOS_COLOR_PANEL_ACTIVE` only, deliberately avoiding `RATIMOS_COLOR_ACCENT` inside the artwork itself so icons stay visible against the badge's accent-red circular background.
- `colombiaOS` is named exactly once in the whole repository (`docs/visual-identity/README.md`'s Distinctness section) — every other file, including `assets/icons/README.md`, uses generic wording, satisfying this plan's own zero-hits-elsewhere acceptance gate.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Self-defeating grep: header comment's own mention of the format name broke its own acceptance count**
- **Found during:** Task 1 acceptance-criteria verification (`grep -c 'LV_COLOR_FORMAT_I4' icons.c` expected 11, got 12)
- **Issue:** The generated-file header comment explaining the pixel format literally contained the string `LV_COLOR_FORMAT_I4`, adding a 12th match on top of the 11 real per-image occurrences.
- **Fix:** Reworded the header comment to describe the format in prose without the literal macro name.
- **Files modified:** `tools/convert_images.py`
- **Verification:** `grep -c 'LV_COLOR_FORMAT_I4' src/ratimos/icons.c` returns 11.
- **Committed in:** `befa1c4` (Task 1 commit)

**2. [Rule 1 - Bug] Generated font's `#ifdef LV_LVGL_H_INCLUDE_SIMPLE` fallback broke the build**
- **Found during:** Task 2, first `pio run -e native_sim` after generating the fonts
- **Issue:** `lv_font_conv` emits `#ifdef LV_LVGL_H_INCLUDE_SIMPLE / #include "lvgl.h" / #else / #include "lvgl/lvgl.h" / #endif`; this project defines `LV_CONF_INCLUDE_SIMPLE` (a different macro) and every other file just does `#include "lvgl.h"` directly (see `logo_image.h`), so the `#else` branch fired and failed to find `lvgl/lvgl.h`.
- **Fix:** `convert_title_font.sh` now post-processes the generated file with `sed`, collapsing the ifdef block to the single `#include "lvgl.h"` line the rest of the project already uses — kept in the script (reproducible), not hand-edited into the generated `.c` files.
- **Files modified:** `tools/convert_title_font.sh`
- **Verification:** `pio run -e native_sim` exits 0 with both font files compiled in.
- **Committed in:** `51e0bf8` (Task 2 commit)

**3. [Rule 1 - Bug] Missing `LV_USE_FONT_COMPRESSED` silently dropped every glyph**
- **Found during:** Task 2, headless smoke run of the built simulator binary
- **Issue:** `lv_font_conv` emits compressed glyph bitmaps by default (smaller flash footprint); `lv_conf.h` never enabled `LV_USE_FONT_COMPRESSED` (LVGL default 0), so every glyph draw call warned `Couldn't get the bitmap of a glyph` and rendered nothing — the pixel font would have shipped visually broken despite a clean build.
- **Fix:** Added `#define LV_USE_FONT_COMPRESSED 1` to `lv_conf.h`.
- **Files modified:** `lv_conf.h`
- **Verification:** Re-ran the headless smoke run — zero warnings; screenshot of the live simulator confirms all glyphs render (see Task 3's screenshot evidence).
- **Committed in:** `51e0bf8` (Task 2 commit)

**4. [Rule 1 - Bug] `NULL` icon id would have crashed the letter-fallback path**
- **Found during:** Task 3 implementation, applying the plan's own must-have truth ("`ratimos_badge_create()` called with an unknown or NULL icon id... returns a valid object instead of crashing")
- **Issue:** The fallback branch originally passed `icon_id` straight to `lv_label_set_text()`; a `NULL` icon_id would dereference null inside LVGL's label text handling.
- **Fix:** Guarded with `icon_id ? icon_id : "?"` before the fallback label is set.
- **Files modified:** `src/ratimos/theme.c`
- **Verification:** Code review confirms `ratimos_icon_by_id()` already returns `NULL` safely for a `NULL` id (checked first), and the letter-fallback path never dereferences a raw `NULL` string.
- **Committed in:** `07570b7` (Task 3 commit)
