screenshots. That worked for home -> jogos -> conexo (both first tap). Then the session showed

indev* (the same hit-testing path a real tap takes), counts taps until the active screen
changes, reads the live sectionbar label, and dumps every frame to PNG. I looked at every

### Auto-fixed / adjusted

**1. [Rule 1 - Bug] Topbar opacity constant did not match the approved design it cites**
- **Found during:** Task 3
- **Issue:** The plan prescribes `LV_OPA_60` (keeping the violet panel fill) as "closest" to
  the approved `rgba(0,0,0,0.4)`. LVGL opacity is opacity, not transparency: `LV_OPA_60` is
  60% opaque violet, which is noticeably more solid than the sketch's 40% black.
- **Fix:** `lv_obj_set_style_bg_opa(row, LV_OPA_40, 0)` + `bg_color = lv_color_black()` in
  `ratimos_topbar_create()` only. `bar_row_create()` is unchanged.
- **Verification:** before/after topbar crops from the real SDL sim show the dither pattern
  through the topbar, and the text stays legible. Acceptance grep passes.
- **Commit:** d79f5c1

**2. [Rule 3 - Blocking] Worktree branch was one docs commit behind main**
- The required-reading SUMMARYs (02.1-09, 02.1-11) only existed on main (`bf80966`).
  Fast-forwarded the worktree branch to main before starting. No code involved.

**3. Plan text vs. landed reality (no code impact)**
- The provenance row for `bg_dither` names `tools/convert_bg_dither.py` (RGB565), not the
  plan's `tools/convert_images.py` (the I4 path was superseded in 02.1-09).
- termo.c's "before" state was worse than the plan assumed. The old index read
  (`screen` child 1 -> `row` child 1) resolved to the topbar's right-side container, not a
  label, so every mode switch called `lv_label_set_text()` on a non-label object. The index
  fix (child 2 / child 0) also removes that.

**Total deviations:** 1 Rule-1 adjustment, 1 Rule-3 setup step, 2 documentation-level notes.
