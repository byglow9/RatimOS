# Phase 02.1 Plan 03: Garden-Inside-Castle Progression System Summary

**A versioned, additive-safe progression manifest turning the shared daily-completion counter into a visible garden-inside-castle-grounds reward: six hand-authored stage scenes, five per-game exclusive unlock sprites, a dedicated castelo screen, and a home-screen progression tile.**

## Performance

- **Duration:** ~65 min
- **Completed:** 2026-09-09
- **Tasks:** 3/3
- **Files modified:** 23 (21 created, 2 modified)

## Accomplishments

- `src/ratimos/progression.h`/`.c`: the data-driven progression model RESEARCH's Round 2 specified -- a `RATIMOS_PROGRESSION_MAX_STAGES`-sized manifest with string `asset_id` keys and threshold-based (never switch-based) resolution, so appending stage 7 later is a data edit, not a code edit (D-06a). v1 ships 6 stages / 30-completion end state and five per-game exclusive unlock ids.
- `tools/generate_progress_art.py` + `assets/progress/`: eleven project-authored pixel-art PNGs -- six 288x180 scenes forming one continuous castle-and-garden plot (each stage additive over the last, castle and garden together in-frame from stage 02 onward per D-03) plus five 32x32 per-game unlock sprites (rose bush, pennant, small tree, fountain, gate).
- `src/ratimos/progress_images.c`/`.h`: generated by reusing plan 02.1-02's `tools/convert_images.py` completely unmodified (`git diff --stat` empty), resolvable at runtime through `ratimos_progress_image_by_id()`, a thin delegation living in the progression module rather than the generated file.
- `src/ratimos/apps/castelo_app.c`/`.h`: the dedicated castelo screen -- cache-once but **refresh-on-every-visit** (the first screen in this codebase whose cached content actually changes between visits), showing the current stage image, the status-copy-by-stage caption (zero/mid-range/complete), and a "conquistas" row with locked-but-dimmed / unlocked-at-full-opacity icons.
- `home_screen.c`: a full-width progression tile below the existing 2x2 grid, wired to `ratimos_castelo_show`, re-reading status on every `ratimos_home_screen_show()` so a win in any game shows the updated day count on return without a screen rebuild.
- 12 new Unity tests in `test_progression`, all passing; full relevant suite (`test_storage`, `test_jogos_conexo`, `test_progression`, `test_storage_game_state`) at 48/48.
- Manually verified via real simulator screenshots (see Deviations) at both a mid-progress state (dimmed/unlocked icon split) and the end state (`castelo completo! parabens`), reading from a hand-crafted `assets/save/progression.bin` fixture -- confirming persistence-driven rendering actually works end to end, not just in unit tests.

## Decisions Made

- Bumped `asset_id[32]` to `asset_id[40]` before the first commit -- the plan's own literal stage-04 asset id is 37 characters and would have silently truncated in the 32-byte field the RESEARCH doc proposed; caught by a compiler warning during the very first test run, not by any acceptance grep.
- Progression art palette extends the locked chrome palette with a small garden-only set (two greens, one dirt/trunk brown), mirroring `theme.h`'s existing game-semantic-color precedent -- never used as chrome/CTA, scoped entirely to this one visual domain.
- Per-game exclusive unlock motifs (D-05, Claude's discretion) chosen for 32x32 legibility and garden-decoration theming: rose bush (sudoku), pennant (paciência), small tree (termo), fountain (cruzadinha), gate (conexo).
- `castelo_app.c` is the first cache-once screen in this codebase that must **refresh, not just cache**, since its content (stage image, caption, unlock opacities) genuinely changes between visits as the shared counter grows -- `refresh_castelo_screen()` runs on every `ratimos_castelo_show()` call, distinct from every prior screen's build-once-and-never-touch-again pattern.

What remains genuinely unautomatable is the literal tap sequence (home screen -> tap castelo tile -> confirm navigation) and playing an actual game to completion end-to-end through touch input -- logged as an open `unrun-verify` item in `WINDOWS.md`.
