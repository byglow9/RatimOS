    **1. `tools/convert_images.py` (new, generalises `convert_logo.py`).** Same shebang, same
    `REPO_ROOT = Path(__file__).resolve().parent.parent` idiom, same Pillow dependency (already a
    project dependency — add no new package). It is manifest-driven so plan 02.1-03 can reuse it
    unchanged for progression artwork: it takes `--manifest <path>`, `--out-c <path>`,
    `--out-h <path>`, and `--guard <MACRO>` on the command line. The manifest is a JSON object with
    a `symbol_prefix` string and an `images` array of `{ "id": "...", "file": "...", "w": N, "h": N }`
    entries whose `file` is relative to the manifest's own directory.

    Emit `LV_COLOR_FORMAT_I4` rather than the logo's RGB565 (UI-SPEC step 3 — pixel art uses few
    colors and I4 is roughly a quarter the flash footprint, which matters once these compile into the
    real ESP32-S3 image). That means a genuinely new packing routine, not a copy of `rgb565_bytes()`:
    quantise each source image to at most 16 colors with Pillow's palette conversion, emit the
    16-entry palette as 4 bytes per entry in LVGL's blue-green-red-alpha byte order **before** the
    pixel data, then pack two 4-bit palette indices per byte, row-major, with each row padded to a
    whole byte. Set `.header.stride` to the padded per-row byte count. Reuse `emit_c_array()`'s
    16-bytes-per-line formatting verbatim.

    Every emitted `.c` and `.h` gets the project's generated-file header comment in the existing
    PT-BR style, naming `tools/convert_images.py` and the manifest path as its source and stating it
    must not be hand-edited.

    The generated `.c` also emits a lookup table and
    `const lv_image_dsc_t * <prefix>_by_id(const char * id)` that walks the table and returns the
    **first** entry whose id matches (documented in a comment so a duplicated id resolves
    deterministically), returning `NULL` for `NULL` or an unmatched id. The generated `.h` emits one
    `extern const lv_image_dsc_t <prefix>_<id>_desc;` per entry plus the `_by_id` prototype, wrapped
    in the `--guard` include guard.

    **2. Icon source art (`assets/icons/`).** Author eleven 32x32 pixel-art PNGs with transparent or
    `#000000` backgrounds, matching the logo's blocky 16-bit treatment and its red/violet palette

    #4e2277, `RATIMOS_COLOR_TEXT` #f5f2f8) so the icons read as one family with the existing chrome
    and never introduce a color outside that family. Ids, exactly: `home_jogos`, `home_musica`,

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet → dev machine (`npx lv_font_conv`, downloaded TTF) | Third-party code and a third-party binary font cross into the build at dev time. Neither ships as a firmware dependency; both influence committed generated source. |
| source PNG/TTF → generated C compiled into firmware | A malformed or oversized source asset produces C arrays that are compiled and rendered on device. |
