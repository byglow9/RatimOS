# Phase 02.1 Plan 13: 003-C bevel on every card, button and keyboard Summary

**Full 003-C double-frame bevel (dark border + inner light frieze + dark band) drawn in LVGL draw callbacks with no child objects, shared by all panels, a new `ratimos_button_create()`, the three game keyboards and the bottombar 'voltar'. Also fixes the clipped/cramped button layouts.**

## Accomplishments
- Added `ratimos_bevel_apply()`, which completes the 003-C frame skipped in 02.1-09. The frieze is drawn with `lv_draw_rect` (border only) in `LV_EVENT_DRAW_POST`. The callback is registered once per object and no `lv_obj_create` is involved. `ratimos_panel_create()` now delegates to it.
- Added `ratimos_button_create()` and `ratimos_button_set_selected()`. They replace the local `make_pill`/`make_pill_w` helpers in conexo, sudoku, termo, cruzadinha and paciencia, keeping the same tree (panel -> 1 label). Sudoku and termo mode pills no longer drop their border when unselected.
- Added `ratimos_bevel_style_buttonmatrix()`. Keys are radius 0, PANEL at OPA_70, with a 2px BEVEL_DARK border and PANEL_ACTIVE when pressed or checked. The per-key frieze comes from `LV_EVENT_DRAW_TASK_ADDED` on FILL tasks of `LV_PART_ITEMS`. The container's outer pad is set to 0 so keys are no longer squashed.
- Fixed the button layout issues from deferred-items #5:
  - Sudoku keypad is now 2 rows, so "9apagar" no longer runs together.
  - "proxima palavra" is content-sized and no longer clipped.
  - Conexo action pills are square bevels.
  - Termo "enter"/"apagar" and cruzadinha "apagar" got wider keys.
- The bottombar 'voltar' is now a bevel button (pad 8/2, TEXT color, keeps LV_SYMBOL_LEFT). The bar grows from 22 to 28px.
- Termo letter cells changed from radius 2 to 0. No chrome in `src/ratimos` has radius > 0 any more, except paciencia's playing cards.

## Decisions Made
- The frieze follows the object's current border width rather than a hard-coded 2px. Some callers change the border at runtime (for example conexo tiles switch between 1px and 2px), and the frieze always sits just inside it. Border 0 means no frieze.
- The buttonmatrix item `border_opa` uses `LV_OPA_100` (same value as COVER), so the literal "no `LV_OPA_COVER, LV_PART_ITEMS`" criterion holds. Key backgrounds stay at OPA_70.
- On termo, "enter" and "apagar" get 3 units each. With 2 units the text touched the bevel. The trade-off is narrower z–m keys (~20px). The user reviewed this at the checkpoint, and touch-size validation stays with the Phase 3 hardware check.
- The 2-row sudoku keypad makes the screen scroll a little to reach row 2. Before this, the 1-row keypad was already partly cut off.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Termo mode pills had the same border-dropping `render_pills()` as sudoku**
- **Found during:** Task 2
- **Issue:** The plan only called out sudoku's `render_pills()`. Termo's version also set the border to 0 when unselected and accent red when selected, which breaks the "selection never removes the bevel" truth.
- **Fix:** Termo's `render_pills()` now uses `ratimos_button_set_selected()`. The now-unused `s_pill_labels` arrays were removed from both games.
- **Files modified:** src/ratimos/apps/jogos/termo.c, sudoku.c
- **Commit:** f09c7db

**2. [Rule 1 - Bug] Buttonmatrix default theme padding squashed the keys**
- **Found during:** Task 2 (headless frame check)
- **Issue:** The LVGL default theme puts about 10px of outer padding around a buttonmatrix, so keypad keys rendered about 16px tall.
- **Fix:** `ratimos_bevel_style_buttonmatrix()` sets the container `pad_all` to 0. This leaves the caller's `pad_row`/`pad_column` untouched.
- **Commit:** f09c7db

**3. [Rule 1 - Bug] Termo letter cells used radius 2**
- **Found during:** Task 2 acceptance grep
- **Fix:** Radius set to 0, as the acceptance grep requires.
- **Commit:** f09c7db
