## Decisions Made

- `ratimos_conexo_start()` preserves the `ratimos_puzzle_history_t history` field internally across its own state reset, so every caller (first play, "novo jogo", corrupted-save recovery) automatically keeps the non-repeat history without needing to save/restore it manually.
- Daily-win recording lives in a standalone `ratimos_conexo_record_win_if_needed()` engine function (LVGL-free) rather than inline in the screen's submit callback, so the once-only guard against double-counting is directly unit-testable.
- The "novo jogo" destructive-reset confirm dialog is a hand-rolled cache-once overlay (built once, shown/hidden via `LV_OBJ_FLAG_HIDDEN`), not `lv_msgbox`, consistent with the phase's "no third-party UI blocks" stance.
- New UI copy (confirm dialog text, "+1 no castelo" line) stays ASCII-only, following the precedent Task 1 already set for the error/loss copy — the project's bitmap fonts are documented ASCII-only, so the UI-SPEC's literal accented Portuguese text was rendered as unaccented equivalents (meaning preserved, glyphs guaranteed to render).
- The `actions` button row switched from `LV_FLEX_FLOW_ROW` to `LV_FLEX_FLOW_ROW_WRAP` to fit a third pill ("novo jogo") without overflowing the 300px content box.

**1. [Rule 1 - Bug] Missing `<stdio.h>` include in conexo.c**

- **Files modified:** `src/ratimos/apps/jogos/conexo.c`

- **Committed in:** `88f6a3d` (Task 1 commit)

**2. [Rule 1 - Bug] `games.c`'s own D-02 comment defeated its own acceptance-check grep**
- **Found during:** Task 1 acceptance-criteria verification (`grep -c 'car jam' src/storage/games.c` expected 0, got 1)
- **Issue:** The comment explaining the removal of the "car jam" placeholder literally contained the string `"car jam"`, so the grep-based acceptance check meant to confirm the placeholder was gone instead matched the comment describing its removal — the same self-defeating-grep pattern already documented as fixed once before in 02-03 (cJSON-confinement comment).
- **Fix:** Reworded the comment to describe the removed concept without the literal phrase.
- **Files modified:** `src/storage/games.c`

**3. [Test design fix, caught before commit] Statistically flaky history-avoidance test**
- **Found during:** Task 2 test authoring, first local run of `test_jogos_conexo`
- **Issue:** The first draft of `test_puzzle_pick_avoids_history_loaded_index` marked 4-of-5 puzzles as recent and asserted a single fixed seed always found the one remaining candidate within `ratimos_puzzle_pick`'s 16-attempt budget. `ratimos_puzzle_pick`'s documented "honest scaling limit" (falls back to a repeat after exhausting attempts) meant this had a real, non-zero failure chance (~2.8% for the chosen seed) and it failed on the very first run.
- **Fix:** Redesigned the test to mark only 2-of-5 as recent and assert non-membership (not an exact index) across 20 different seeds — failure probability now ~4e-7, and the assertion matches what `ratimos_puzzle_pick`'s contract actually guarantees rather than something stronger than the implementation promises.
- **Files modified:** `test/test_jogos_conexo/test_jogos_conexo.c`
- **Verification:** 13/13 tests pass, reproducibly.
- **Committed in:** `f115025` (Task 2 commit — the flaky version was never committed)

## Issues Encountered

- **No GUI input-simulation tooling available.** This execution environment has no `xdotool`/`wmctrl`/equivalent and no `sudo` access to install one, so the plan's interactive simulator acceptance criteria (Task 1: tap jogos > conexo > select 4 > enviar > voltar > relaunch > same board; Task 3: delete/corrupt `assets/save/conexo.bin`, relaunch, visually confirm fresh board + error copy) could not be executed as literal manual click-throughs. Substituted with: (a) 29 passing unit tests covering every state transition those manual steps would exercise, (b) a headless 3-second run of the compiled binary with a corrupted `conexo.bin` present, confirming no crash/signal, and (c) direct code review confirming the screen-build wiring (`load_or_start_state()`, `persist_state()` called after every interaction, error label shown once per screen build via a static flag pattern). Logged as two `unrun-verify` entries in `.planning/WINDOWS.md` (phase 02.1) for a human or a future display-automation-capable session to close out.
- **Tracer feedback gate not paused on.** Per the standard executor workflow, Task 1 is `type="tracer"`, and with `AUTO_CFG`/`AUTO_CHAIN` both `false` in `.planning/config.json`, the default protocol would have stopped for a `checkpoint:human-verify` immediately after Task 1's commit, before starting Task 2. This session's explicit resume instructions (rate-limit recovery, `success_criteria` requiring Tasks 1-3 and SUMMARY.md all completed in one continuous run) directed proceeding through all three tasks instead. Documented here as an explicit, deliberate deviation from the standard checkpoint protocol, made at the spawning orchestrator's direction rather than the executor's own initiative.
