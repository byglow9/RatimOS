    **`src/ratimos/apps/jogos/sudoku_engine.c` (new).** Implement:
    - *Validity*: standard row/column/3x3-box scan, ignoring the target cell itself.
    - *Counting solver*: the RESEARCH pattern — find the first empty cell, try digits 1-9 that pass
      validity, recurse with a decreasing remaining limit, and stop as soon as the running total
      reaches `limit`. A puzzle is uniquely solvable exactly when the count with `limit = 2` is 1.
      Do not substitute a heuristic; this is the one non-negotiable correctness gate for the game.
    - *Generation*: seed a local PRNG from `seed` (use a small self-contained xorshift32 rather than
      the global `rand()`/`srand()` so tests are deterministic and independent of call order), fill a
      complete valid grid by randomized backtracking, copy it to `solution`, then remove clues one at
      a time in a shuffled cell order — after each removal, run the counting solver and put the digit
      back if uniqueness was lost — until the remaining clue count reaches the mode's target band.
      Bands: easy 40-45, medium 30-35, hard 22-27, and daily uses the medium band. Cap total work
      with `max_attempts` (default the callers pass is 64); returning false on exhaustion must leave
      `*out` untouched so the caller can show the generation-failure copy. Add a comment stating
      plainly that clue count is a proxy for difficulty, not solver-technique-based grading — this is
      an accepted simplification for a personal gift, and the label must not claim more than that.
    - *Daily*: `ratimos_sudoku_generate_daily()` calls `ratimos_sudoku_generate()` with
      `RATIMOS_SUDOKU_DIARIO`, the caller-supplied day seed, and the same attempt cap, so the same
      calendar day always yields the same board with no network involved.
    - *Play helpers*: `set_cell` refuses to write a cell whose `given` value is non-zero and refuses
      a digit above 9; `cell_conflicts` reports whether the player's entry at that cell duplicates
      another non-zero entry in its row, column, or box; `is_solved` is true only when every cell is
      non-zero across `given`/`filled` combined and no cell conflicts.

    **`test/test_jogos_sudoku/test_jogos_sudoku.c` (new).** One test per bullet in `<behavior>`,
    using two hand-written fixture boards (one uniquely solvable, one with multiple solutions) and a
    contradictory board. The 20-consecutive-generations uniqueness test is the load-bearing one; keep
    it inside a loop over the three playable difficulties so a regression in any band fails loudly.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| disk → sudoku state | The 9x9 boards, mode, cursor, and win-guard flag are restored from an untrusted save blob and used to index fixed 9x9 arrays. |
