<objective>
Deliver the second half of JOGOS-01: Klondike solitaire (D-01's chosen variant), fully playable with
simulated touch, with every move routed through explicit per-move-type legality checks so an illegal
move can never be silently accepted, and with the whole deal persisted through the Storage/Content
API domain plan 02.1-01 established.

Purpose: RESEARCH's Don't-Hand-Roll table names "cards silently accepting illegal moves" as the
common, hard-to-debug solitaire-clone failure. Centralising legality in one testable function per
move type is what makes that failure impossible rather than unlikely.

    **`src/ratimos/apps/jogos/klondike_engine.c` (new).**
    - *Deal*: build the 52-card ordered deck, shuffle it with Fisher-Yates driven by the same local
      xorshift32 PRNG style the sudoku engine uses (never the shared global generator, so tests stay
      independent of call order), then deal 1..7 cards to the seven tableau columns face-down with
      only the last card of each column face-up, and put the remaining 24 in the stock face-down with
      an empty waste and four empty foundations.
    - *Legality*: implement `can_move` as a `switch` over the move kind with one small, separately
      readable helper per kind, so each rule is independently testable and independently reviewable.
      Every helper bounds-checks its pile indices against the pile counts before touching an array.
      A multi-card tableau-to-tableau move is legal only if the moved run is itself a valid
      descending alternating-colour sequence and all of its cards are face-up.
    - *Mutation*: `ratimos_klondike_move()` must call `can_move` first and return false without
      touching a single byte of state when it says no. On success, move the cards, increment `moves`,
      auto-flip a newly exposed face-down tableau card, and recompute `won` via
      `ratimos_klondike_is_won()`.
    - *Recycle*: with an empty stock and a non-empty waste, `RATIMOS_KLONDIKE_MOVE_RECYCLE_WASTE`
      returns the waste to the stock preserving order and flipping the cards face-down. With a
      non-empty stock it is illegal.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| disk → klondike state | Every pile, count, and flag is restored from an untrusted save blob and used to index fixed-size card arrays. |
| UI move requests → engine | The screen may request any move kind with any indices; the engine is the only place that decides legality. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
