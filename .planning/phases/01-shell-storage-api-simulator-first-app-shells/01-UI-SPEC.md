# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Platform note:** RatimOS is an embedded LVGL 9.5 / PlatformIO-native project (C, SDL2 simulator), not a web/React stack. The shadcn initialization gate does not apply — there is no `components.json`/npm design-system tooling in this repo, and none is planned. This UI-SPEC adapts the standard GSD template's intent (spacing/typography/color/copy contracts) to the project's existing hand-rolled LVGL theme layer (`src/ratimos/theme.c/.h`), which was already established in the Phase 0 baseline and is confirmed here rather than re-invented.

## Design System

| Property | Value |
|----------|-------|

## Spacing Scale

**Exception declared up front:** this project's Phase-0 baseline already established a **2px-multiple micro-scale** (4/6/8/10) rather than the standard 4/8/16/24/32/48/64 8-point scale, because the physical target is a 320×480 3.5" panel where 8px increments consume proportionally more of the available width than on a desktop/mobile web canvas. Phase 1 preserves this convention unchanged for all existing shell/app code, and the new splash screen follows the same scale for consistency. Larger tokens (16/24) are reserved for the few genuinely major layout breaks (splash logo-to-bar gap, screen-edge content padding).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Badge-to-label gaps, tile internal row gaps (`tile_create` pad_row) |
| sm | 6px | Sectionbar icon-to-title gap, topbar right-cluster column gap |
| md | 8px | Panel/card internal padding (`ratimos_panel_create`), album grid column gap, splash bar-to-percentage-label gap |
| lg | 10px | Screen-edge content padding (`shell.content`/home `content` pad_all), row-list column gap, content flex pad_row |
| xl | 16px | Splash logo-to-loading-bar vertical gap (new, this phase) |
| 2xl | 24px | Splash screen top/bottom margin (new, this phase) — matches existing bar heights (22-26px) so the splash reads as "one more screen," not a visually distinct interstitial |

Exceptions: touch-target sizing (e.g. the 44px minimum tap target guideline) is **not** enforced in Phase 1 — the simulator uses SDL2 mouse input (`lv_sdl_mouse_create`), and exact touch-target px minimums only become safety-critical once the real FT6336 capacitive panel is calibrated in Phase 3 (INPUT-01/INPUT-02). Existing badge size (28×28px) and bar heights (22-26px) are below the eventual 44px guideline and should be revisited in Phase 3 planning, not blocked on here.

## Typography

LVGL's bundled Montserrat is a **bitmap/vector font family with exactly one visual weight per compiled size** — there is no bold face available without shipping a second font asset (flash-cost tradeoff, out of scope for Phase 1). Hierarchy in this project is therefore built from **size + color** (`RATIMOS_COLOR_TEXT` vs `RATIMOS_COLOR_TEXT_MUTED` vs `RATIMOS_COLOR_ACCENT`), not weight. Where the standard template asks for "2 weights," read this project's equivalent as "2 color tiers" (primary text vs muted text) layered on top of 3 fixed sizes.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label (badges, topbar brand, bottombar hints) | 14px (`lv_font_montserrat_14`, project default) | regular (only weight compiled) | 1.2 (LVGL built-in font metric, not independently configurable per-label) |
| Body (row titles/subtitles, list items, empty-state copy) | 14px | regular | 1.2 |
| Heading (section-bar title, splash wordmark support text) | 20px (`lv_font_montserrat_20`) | regular | 1.2 |
| Display (splash logo/wordmark) | 28px (`lv_font_montserrat_28`) | regular | 1.2 |

Color-as-hierarchy substitute:
- Primary text: `RATIMOS_COLOR_TEXT` (`#f2eeff`) — row titles, active labels, splash wordmark.
- Muted text: `RATIMOS_COLOR_TEXT_MUTED` (`#a89fd1`) — subtitles, bottombar hints, empty-state body copy, splash step captions (if used).
- Accent text: `RATIMOS_COLOR_ACCENT` (`#6dd6c4`) — brand wordmark in the topbar, back-button label, section-bar checkmark — see Color section below for the full reserved-for list.

## Color

Existing tokens (`src/ratimos/theme.h`), confirmed unchanged for Phase 1:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#14102b` (`RATIMOS_COLOR_BG`) | Screen background on every screen (home, splash, all 5 apps) |
| Secondary (30%) | `#2b2358` (`RATIMOS_COLOR_PANEL`), `#4a3f8f` (`RATIMOS_COLOR_PANEL_ACTIVE`) | Topbar/sectionbar/bottombar bar fills, panel/card/row/tile backgrounds; `_ACTIVE` variant reserved for pressed/active tile state (not yet wired to a pressed style in Phase 0 code — flagged below as a UI consideration, not a blocker) |
| Accent (10%) | `#6dd6c4` (`RATIMOS_COLOR_ACCENT`) | Reserved for: topbar brand wordmark text, section-bar checkmark icon (`LV_SYMBOL_OK`), bottombar back-button label/arrow, badge circle fill (the round letter-badge used in tiles/rows), **and** the splash screen's loading-bar fill (new, this phase) |
| Destructive | none defined | No destructive actions exist in Phase 1 scope (read-only navigation + browsing mock content). Deferred to whichever future phase introduces delete/reset actions (candidates: Phase 6 settings reset, Phase 9 game-state reset) — do not invent a destructive color token speculatively now. |

**Caveat for the checker:** every `ratimos_panel_create()`-based surface (panels, rows, tiles) currently draws a **1px accent-colored border** in addition to the reservations above. This is a pre-existing Phase-0 pattern applied broadly, which on paper looks like it violates "accent reserved for specific elements only." It is intentionally preserved here (not redesigned in Phase 1, which is a plumbing phase, not a visual-identity phase — that's Phase 9/VISUAL-01) but flagged explicitly so the checker treats it as a **known, accepted exception** rather than a silent violation: the border is a 1px hairline (minimal perceptual area at 16-bit color depth on a 320×480 panel), not a fill, so it does not meaningfully compete with the accent's true 10%-of-visual-weight budget.

Accent reserved for (explicit list — do not expand without a Phase 9 visual-identity pass): brand wordmark, section-bar checkmark icon, back-button, round letter-badges, splash loading-bar fill, [accepted exception] panel/row/tile 1px hairline borders (inherited, not new).

## UI Considerations

Applicable state considerations resolved: 6 covered, 2 backstop, 4 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| loading | Splash loading bar (`interactive-control`) | ✅ covered | Bar is driven by real, named storage-init steps (mount → index photos/tracks/letters/games/settings) per D-02/D-03/Pattern 2 — never a cosmetic/fake timer. |
| empty | cartas list, musica list (`list-collection`) | ✅ covered | Existing established copy rows (see Copywriting Contract) already exist in `cartas_app.c`/`musica_app.c`; must become **conditional** on real Storage API count instead of the current unconditional hardcoded row — see "partial"/dismissal note below. |
| empty | album grid, jogos list (`list-collection`) | ✅ covered | New copy defined above in Copywriting Contract; wire conditionally on `ratimos_storage_list_*()` returning 0. |
| loading | cartas/musica/jogos/config lists, album grid (`list-collection`) | dismissed | Storage API is synchronous (D-10) and all content is pre-indexed during the splash sequence (Pattern 2) before `ratimos_home_screen_show()` is ever reachable — by the time any app screen opens, its data is already resident in memory. No per-screen loading state exists or is needed this phase. |
| populated | cartas/musica/jogos/config lists, album grid (`list-collection`) | ✅ covered | Happy path is 3-4 items per domain (D-13), rendered via the existing `ratimos_row_create()`/tile patterns — already proven to handle >1 item visually (jogos already renders 3 static rows today). |
| nav | Home screen 5 section tiles (`nav`) | ✅ covered | Section labels are fixed, short, known strings (jogos/musica/album/cartas/config) — no truncation/long-text risk. |
| overflow / long-text | Row titles/subtitles (`ratimos_row_create`), album tile labels (`list-collection`) | ⚠ unresolved | `row_list.c` and the album/home tile labels do not currently set an `lv_label` long-mode (no `LV_LABEL_LONG_MODE_DOT`/`WRAP`). This was a non-issue while all titles were short hardcoded placeholders, but becomes a real risk once real fixture titles (e.g. longer letter/track names) flow through the Storage API. Planner should add explicit long-mode truncation (recommend `LV_LABEL_LONG_MODE_DOT`) to title/subtitle labels in `row_list.c` and photo-tile labels in `album_app.c`. |
| zero-one-many | Track/photo/letter/game counts in row subtitles (e.g. "0 faixas") (`list-collection`) | ⚠ unresolved | Portuguese distinguishes singular/plural ("1 faixa" vs "2 faixas"); the current hardcoded "0 faixas" string doesn't branch on count. Now that counts come from the real Storage API, planner should add simple singular/plural copy branching wherever a count is interpolated into subtitle text. Low severity (cosmetic), not blocking. |
| partial | letter/track/game fixtures with a missing title field (`list-collection`) | ⚠ unresolved | Fixtures are hardcoded/manifest-driven per Pitfall 4, so a missing title is a developer authoring error, not a real runtime path — but the Storage API's list functions should still return a safe default label (e.g. "sem titulo") rather than an empty/garbage string if a fixture field is blank, as cheap defensive coding. Not blocking for Phase 1. |
| error | Splash storage-init step failure (missing/malformed fixture file) (`interactive-control`) | 🧪 backstop | See Copywriting Contract's optional error-state copy. Recommended default exists but is not wired/tested this phase; if the planner does add a fallback path, it should be covered by a held-out test in `test/test_storage/` (e.g. "list function returns 0 gracefully on a missing manifest entry, does not crash") rather than assumed to silently pass. |
| overflow | Splash wordmark / logo at 28px display size (`static-content`) | dismissed | "RatimOS" at 28px comfortably fits the 320px screen width with the declared 24px top/bottom margins; no dynamic/user-controlled text is ever placed here, so wrapping/truncation risk is zero by construction. |
