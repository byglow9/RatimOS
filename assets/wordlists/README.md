# Termo/Dueto/Quarteto word lists — provenance and manual review record

This directory holds the intermediate, human-reviewable text files behind the compiled
`src/ratimos/apps/jogos/termo_words.c`/`.h` arrays (JOGOS-03, D-01b). It exists specifically so
the answer pool a real person reads every day can be checked and edited by hand before it is
compiled into firmware — see "Manual suitability pass" (revisao manual de adequacao) below.

## Files

| File | Contents | Generated by |
|------|----------|--------------|
| `termo_answers.txt` | The curated daily-answer pool (577 words after manual review) — one lowercase, unaccented, 5-letter word per line, sorted alphabetically | `tools/curate_termo_words.py` (candidate), then hand-edited (final) |
| `termo_accepted.txt` | The wider accepted-guess list (6,011 words) — every filtered 5-letter entry from the source lexicon, sorted alphabetically for binary search | `tools/curate_termo_words.py` |

## Source

**`fserb/pt-br`** (https://github.com/fserb/pt-br) — a ~145,744-entry raw Brazilian Portuguese
lexicon with bundled ICF (inverse-corpus-frequency) scores. **License: MIT**, verified directly
against the repository's `LICENSE` file (Copyright 2021 Fernando Serboncini). 327+ stars, a real
maintained repository, not an abandoned or hallucinated project.

No fallback was needed for this plan — the primary source (`fserb/pt-br`) was reachable and its
structure (a `lexico` word list, an `icf` frequency-score CSV, and a `listas/negativas`
profanity/slur blocklist) matched what RESEARCH.md described. The VeroBP/LibreOffice
Brazilian-Portuguese hunspell dictionary (LGPL-3.0-or-later / MPL-1.1) documented as D-01b's
fallback was **not used**.

## Curation pipeline (`tools/curate_termo_words.py`)

1. Read every entry of the raw lexicon (145,744 entries).
2. Normalize Portuguese diacritics to their unaccented ASCII base (NFKD decomposition, strip
   combining marks — e.g. `avião` → `aviao`) and keep only entries whose **normalized** form is
   exactly 5 letters. Two source entries that normalize to the same ASCII form collapse into one
   entry (253 collapses this run); the one with the better — lower — ICF score is kept as the
   representative for frequency ranking.
3. Drop anything capitalized in the source (proper-noun filter) and anything containing a
   non-letter character after normalization. **Caveat, documented honestly:** `fserb/pt-br`'s
   `lexico` file ships 100% lowercase — this run found 0 capitalized entries, so this specific
   filter was a no-op against this source. See "Manual suitability pass" below for how proper
   nouns that slipped through this gap were caught instead.
4. Cross-reference the source's own `listas/negativas` blocklist (a 340-entry PT-BR
   profanity/slur list bundled in the same repository) and drop any match (37 dropped this run).
   This is a low-effort automatic first pass, **never a substitute** for the manual review below.
5. Rank the remaining ~6,011 entries by ICF score (lower = more common) and keep the 600 most
   common as the answer-pool **candidate**; keep the full filtered set as the accepted-guess list.
6. Write `termo_answers.txt` (candidate, pre-review) and `termo_accepted.txt` for human review,
   then stop — C-array generation happens from whatever is currently on disk in these two files,
   so re-running the script never silently overwrites a manual edit (see the script's own
   `--regenerate` flag docstring for the exact two-phase contract).

## Manual suitability pass (REQUIRED, performed)

**A frequency filter does not remove profanity, slurs, medical/morbid terms, or proper nouns
that a raw lexicon's lowercase-everything convention lets slip past step 3 above — only a human
read-through does.** This pass was performed end to end over all 600 candidate answers before
they were locked in as `termo_answers.txt`.

**23 entries were removed**, in two categories:

**Proper nouns (personal names, countries, Brazilian states) that the automated capitalization
filter could not catch** because `fserb/pt-br`'s lexicon file has no capitalization at all (step 3
above is a documented no-op against this specific source — this is exactly the gap a human pass
exists to close):
`abreu, bruno, ceara, celso, cesar, chico, chile, china, egito, goias, india, japao, julio,
maria, moura, nunes, piaui, sousa, vasco` (19 entries — personal names/surnames and
country/Brazilian-state names that would read as "wrong" or unfair answers in a daily word
puzzle meant to be common-vocabulary).

**Morbid or religiously-loaded terms**, per this plan's explicit prohibition against content
"likely to distress the recipient — every answer is read by exactly one person":
`diabo` (devil), `morte` (death), `morto` (dead/dead body) (3 entries).

That totals 23 removed entries (600 → 577 final answers). Words with negative-but-mundane,
everyday connotations (`abuso`, `crime`, `crise`, `culpa`, `falha`, `lesao`, `preso`, `risco`,
`roubo`) were deliberately **kept** — they are ordinary, frequently-used vocabulary (news,
conversation, general use), not profane, not slurs, and not medically/morbidly framed; removing
every word with any negative connotation would make the pool unrepresentative of real PT-BR
vocabulary. This judgment call is recorded here so a future regeneration pass can apply the same
standard rather than re-litigating each borderline word from scratch.

None of the 577 final answers were found to be profane, slurs, medical/morbid, or otherwise
likely to distress the recipient.

**This pass must be repeated whenever the answer pool is regenerated** (i.e. whenever
`tools/curate_termo_words.py` is run with `--regenerate` against a refreshed or different source
lexicon) — a new frequency ranking can surface different candidate words, and the automated
blocklist/capitalization filters have the same documented gaps against this source every time.

## Regeneration

```bash
# First run (or --regenerate): rebuilds termo_answers.txt/termo_accepted.txt from a source
# checkout of fserb/pt-br (a directory containing `lexico`, `icf`, `listas/negativas`) —
# THIS DISCARDS ANY MANUAL EDITS, so the manual suitability pass above must be repeated
# after running with --regenerate.
python3 tools/curate_termo_words.py --source <path-to-fserb-pt-br-checkout> \
    --out-c src/ratimos/apps/jogos/termo_words.c \
    --out-h src/ratimos/apps/jogos/termo_words.h \
    --answers-max 600 --regenerate

# Subsequent runs (no --regenerate, the default): termo_answers.txt/termo_accepted.txt are
# left exactly as they are on disk (manual curation preserved) — only the compiled C arrays
# are recompiled from whatever is currently in the two .txt files.
python3 tools/curate_termo_words.py --source <path-to-fserb-pt-br-checkout> \
    --out-c src/ratimos/apps/jogos/termo_words.c \
    --out-h src/ratimos/apps/jogos/termo_words.h
```

Both phases are deterministic for a fixed source and a fixed `termo_answers.txt`/
`termo_accepted.txt` pair — re-running either command twice in a row produces byte-identical
generated output.
